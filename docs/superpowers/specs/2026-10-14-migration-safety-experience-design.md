# 随手迁：视觉质感与安全迁移体验改造

日期：2026-10-14  
状态：待用户审阅  
范围：SwiftUI macOS 客户端的视觉语言与应用迁移交互

## 目标

让随手迁在保持“数据安全优先”技术承诺的前提下，呈现更冷静、可信、专业的视觉体验；并使用户在迁移前、迁移中和迁移后均能清楚知道当前状态、风险边界与恢复出口。

用户已确认两项设计决策：

1. 采用 **A：冷静控制台** 视觉方向：浅色留白、低饱和紫色作为唯一强调色、信息先于行动。
2. 采用 **A：先审阅，再确认** 的迁移确认模式：在一次确认页内完整展示目标、空间、备份与验证承诺。

## 非目标

- 不改变 `AppMigrator` 的复制、链接、回滚、备份与操作日志语义。
- 不扩大迁移支持范围，不变更应用更新机制判定策略。
- 不重做体检、数据与设置的业务逻辑；这些页面仅按新的共享视觉组件同步外观。
- 不新增联网、遥测或许可证行为。

## 体验原则

### 1. 安全状态必须可见

高风险操作不能只有一个“开始迁移”按钮。每个迁移计划均要明确呈现：源位置、目标外置盘、预计释放空间、目标盘可用空间、备份可行性、链接策略与完成后验证项。

### 2. 用户只做一次有信息的确认

预检通过后，由用户点击“确认并开始”；预检不通过时，不提供可执行确认，直接说明拦截原因与解决路径。避免多层弹窗和无说明的二次确认。

### 3. 每个执行状态都有可理解的结论

执行期间以阶段时间线表达“预检、备份、复制与切换、启动验证”，同时保留当前文件、百分比与取消操作。完成页给出实际释放空间与“打开应用 / 查看回迁”出口；取消和失败明确说明源数据和临时副本状态。

### 4. 视觉层级服务于决策

使用白色内容卡与细微边缘深度建立层级；品牌紫只用于主操作、当前导航、可继续步骤和信息强调。成功、警告、阻断分别使用绿色、琥珀色、红色，且都配有图标和文字，不能只靠颜色表达。

## 信息架构与流程

```text
应用列表 / 迁移页 / 腾空间建议
              │
              ▼
       生成安全计划（预检）
              │
      ┌───────┴────────┐
      ▼                ▼
  条件不满足         计划审阅
  解释原因 + 修复     用户确认一次
                        │
                        ▼
          预检 → 备份 → 复制与切换 → 启动验证
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
      成功             取消             失败
   释放空间 + 回迁   源应用未动 +     自动回滚结果 +
   / 打开应用        半截副本清理      重试 / 日志入口
```

所有入口最终复用同一份计划审阅体验：单个应用迁移、批量迁移和“腾空间”建议都不得绕过预检或直接开始复制。

## 组件与职责

| 组件 | 职责 | 依赖 |
| --- | --- | --- |
| `MigrationPlanReviewSheet`（新增） | 展示预检结论、迁移项目、空间预算、安全承诺及唯一确认按钮 | 现有迁移规划、磁盘与应用状态 |
| `MigrationPlanViewModel`（新增） | 将现有迁移候选、目标盘信息和预检结果转为可渲染状态；不执行文件操作 | `MigrationPlanner`、`AppState` 的只读数据 |
| `MigrationExecutionView`（新增或从 `MigrationPanel` 拆分） | 渲染阶段时间线、当前文件、进度、取消状态、成功/失败结果 | `MigrationTask` 与迁移回调 |
| `MigrationPanel`（调整） | 作为流程协调入口：请求计划、展示审阅页、确认后调用既有迁移管线 | 新视图模型、现有 `AppMigrator` |
| 共享样式（调整） | 统一卡片、状态徽章、按钮、阶段节点与结果提示的外观 | `MockTheme`、`Design.swift` |

`AppMigrator`、`OperationJournal`、取消令牌和既有备份/回滚代码保持服务层边界；UI 只消费其结果，不能在视图层复刻或绕过安全判定。

## 视图状态

`MigrationPlanViewModel` 仅表达下列状态，保证 UI 分支可测试：

- `loading`：正在聚合应用、目标盘和预检信息。
- `blocked(reasons)`：存在不可迁移、空间不足、外置盘不可用或链接策略不兼容等条件；隐藏执行按钮。
- `ready(summary)`：展示可执行计划与确认按钮。
- `running(phase, progress, currentFile)`：执行时映射既有迁移任务状态。
- `succeeded(summary)`：显示已释放空间、验证完成以及后续入口。
- `cancelled(summary)`：说明已安全停止、源应用未动及半截副本处理结果。
- `failed(summary, recoveryAction)`：展示可读错误、已完成的恢复状态，并提供重试或查看日志。

批量计划在每个应用条目上显示独立状态；单项失败不改变服务层现有的批处理结果语义，只提升可见性。

## 视觉规范

- 侧栏与内容区保留当前分栏结构，选择态用低饱和紫色玻璃/浅底，不新增第二套强调色。
- 页面顶部使用“标题 + 次级状态/刷新”的轻量结构；主要行动位于标题下或计划卡底部，不与刷新、筛选等次级操作竞争。
- 计划审阅页的每一项采用“名称/大小/路径 + 安全校验结果”的两层信息；默认折叠低优先级技术详情。
- 阶段时间线始终显示四个固定节点，当前节点有紫色强调，已完成为绿色，阻断为红色；“取消”作为文本型危险操作，必须携带安全后果说明。
- 所有数值使用等宽数字；动画遵循系统“减少动态效果”设置。

## 错误与恢复

- 计划阶段无法满足条件时，展示具体原因，例如“目标盘剩余空间不足以同时容纳副本与备份”，并列出可操作建议；不能显示模糊的“未知错误”。
- 用户取消时，页面等待既有取消令牌所驱动的清理完成后才显示终态；固定文案说明“源应用未动，半截副本已清理”或如实说明清理异常。
- 迁移失败时，以 `AppMigrator` 结果和操作日志作为唯一事实来源；显示已回滚/待检查状态，不宣称成功。
- 成功后先完成既有启动与链接验证，再显示“迁移完成”；结果页保留回迁入口，不自动删除备份。

## 验证策略

1. 为计划视图模型添加纯逻辑单测：可执行计划、空间不足、外置盘缺失、运行中应用、取消、成功与失败映射。
2. 为迁移 UI 状态补充快照/结构测试，验证阻断状态不渲染确认按钮，成功和取消状态显示正确恢复语义。
3. 运行现有完整 `swift test`，尤其覆盖 `CancellationTests`、`MigrationPlannerTests`、`OperationJournalTests`、`RegressionFixTests` 与迁移相关端到端测试。
4. 手工验证：在接入外置盘、未接入外置盘、目标空间不足及取消迁移四种情形中检查流程与文案。
